Development Philosophy

개발 철학

빠르게 만들되, 이후 변경과 인수인계를 버틸 수 있는 구조를 함께 설계합니다.

핵심 코어 로직을 빠르게 구현

상세 기획과 리소스가 부족해도 레퍼런스 게임을 분석해 핵심 플레이를 우선 구현하고, 빠르게 검증 가능한 MVP를 만듭니다.

확장성 고려

기획이 단순해도 변경 가능성을 염두에 둡니다. 기획 변경이나 기능 수정 등에 유연하게 대처합니다.

쉬운 코드

주석 없이도 의도가 읽히는 구조를 지향합니다. 복잡한 로직은 상세 주석으로 보완하고, 추가/수정/제거가 쉬운 형태로 만듭니다.

제어 가능한 코드

흐름을 예측하기 어려운 코드를 최소화하고, 어디서 시작해 어떤 상태로 이어지는지 개발자가 파악할 수 있는 구조를 선호합니다.

Core Strength

확장 가능한 구조

빠른 핵심 재미 재현코어 플레이 및 MVP를 빠르게 구현하며, 상세 기획서나 리소스가 부족한 상황에서도 레퍼런스 게임 분석만으로 핵심 재미를 빠르게 재현하고 검증 가능하도록 만듭니다.
변경을 고려한 구조 설계단순히 빠르게 구현하는 것에 그치지 않고, 기획 변경과 기능 확장을 고려해 구조를 설계합니다. 읽기 쉬운 코드, 책임이 명확한 구조를 지향합니다.
팀 전체 속도 향상이어받기 쉽도록 구현하여 개인 구현 속도 뿐 아니라 팀 전체의 개발 속도 향상에 기여합니다.
Reusable Game Architecture

공통 게임 시스템 구조

여러 게임 프로젝트에서 반복적으로 사용한 구조입니다. 핵심은 데이터 기반 생성, 명확한 책임 분리, 그리고 기믹 확장성입니다.

Data / Model / View Board 연쇄 생성 이벤트 기반 구조 바인딩 처리 기믹 시스템

Data, Model, View 분리 구조

특정 스테이지에서 생성해야 하는 값은 Data가 담고, 런타임의 실제 상태와 규칙은 Model이 담당하며, Unity 오브젝트와 애니메이션은 View/Object가 담당하도록 분리했습니다.

CellData→Cell→CellObject/CatData→Cat→CatObject

이 분리 덕분에 저장/로드, 스테이지 에디터, 런타임 로직, 연출 수정이 서로 강하게 얽히지 않습니다.

Board에서 하위 모델로 연쇄 생성하고 관리하는 구조

스테이지 전체의 루트는 Board입니다. Board가 Cell을 생성하고, Cell은 자신 위에 놓인 모델을 생성합니다. 이후 상위 Object부터 하위 Object까지 순차적으로 생성합니다.

StageData→Board→Cell→Block / Yarn / Cat / Duck→Object

씬에 오브젝트가 흩어지지 않고, Board 하나를 기준으로 스테이지 전체를 추적할 수 있습니다.

이벤트 기반 후처리 구조

어떤 요소가 제거되거나 상태가 변하면 전체를 무작정 갱신하는 대신, 변화 지점에서 필요한 후처리만 호출합니다. 예를 들어 블록 제거 후 주변 기믹 검사, 경로 재탐색, 스폰 갱신이 이어집니다.

이 구조는 불필요한 전체 재계산을 줄이고, 변화의 원인과 결과를 코드상에서 추적하기 쉽게 만듭니다.

셀 점유 상태와 양방향 바인딩 처리

Cell은 자신 위의 개체를 참조하고, 개체도 자신이 속한 Cell을 참조합니다. setter에서 이전 바인딩을 자동 해제하고 새 바인딩을 연결해, 하나의 개체가 두 위치에 동시에 존재하지 못하도록 보장합니다.

Cell↔Yarn / Cat / Duck / Block·Rail ↔ Duck

오브젝트 이동 연출과 별개로 논리적 소유 관계를 안정적으로 유지할 수 있습니다.

기믹 시스템

Cat, Yarn, Duck, Box, Knit 같은 핵심 개체가 가진 특수 규칙을 bool 필드로 직접 관리하지 않고, 공통 인터페이스와 베이스 클래스로 분리했습니다.

Owner→List<IGimmick>→GimmickData→GimmickObject

기믹은 본체와 분리되어 독립적으로 동작하고 제거되며, 새로운 기믹을 추가할 때 본체 클래스의 수정량을 줄일 수 있습니다. Hidden, Frozen, Switch, Connector 같은 규칙을 기능 단위로 확장할 수 있습니다.

BlossomPackage / NyoPack

자체 프레임워크 패키지

반복되는 Unity 클라이언트 구조를 패키지화해, YarnLoop와 LoopDuck 이후 프로젝트에서 공통 기반으로 사용할 수 있도록 정리했습니다.

왜 만들었나

BlossomPackage는 매 프로젝트마다 다시 작성하던 저장, 리소스 로딩, 오브젝트 생성, UI, 분석, 광고, IAP, 플랫폼 SDK 연동을 작고 명확한 패키지 단위로 나눈 개발 도구 모음입니다.

무겁고 거대한 프레임워크가 아니라, 필요한 기능만 골라 사용할 수 있는 모듈형 패키지를 지향합니다. Provider, Spawner, Service, Handler 같은 인터페이스 기반 구조를 사용해 프로젝트마다 다른 리소스 관리, 프리팹 생성, UI 구조, SDK 조합을 연결할 수 있게 했습니다.

패키지 구성

게임의 핵심 재미는 프로젝트에 남기고, 반복되는 기반 기능은 패키지로 분리했습니다. 작은 프로젝트에서는 빠르게 붙여 쓰고, 규모가 커지는 프로젝트에서는 인터페이스 구현체를 교체해 확장할 수 있게 했습니다.

Blossom.Core컴포넌트 탐색, 리소스 캐싱, 오브젝트 풀링, Entity 생성, 씬 전환, UI 흐름을 정돈하는 기반 패키지입니다.
PersistenceAkiv 기반 로컬 저장 시스템입니다. 값 변경을 감지하고 필요한 타이밍에 저장할 수 있도록 구성했습니다.
Networking온라인 연결 상태 확인, 재시도, 상태 추적을 담당합니다. 광고, IAP, SDK 초기화 전 검증 용도로 사용할 수 있습니다.
AnalyticsFirebase, GameAnalytics, Singular 등 여러 분석 SDK를 하나의 공통 이벤트 API로 묶는 이벤트 허브입니다.
Platform외부 SDK 초기화와 프로젝트 코드를 분리합니다. SDK별 초기화 과정을 얇은 래퍼로 감싸 공통 흐름에 연결합니다.
Monetization광고와 인앱결제 흐름을 통합합니다. 로드, 표시, 보상, 구매, 복원, 수익 분석 전송을 이벤트 중심으로 처리합니다.
Presentation보상 획득 연출, 리뷰 요청, 햅틱 등 표현 계층을 게임 로직과 분리해 연결하는 보조 패키지입니다.
PackageManagerBlossom 패키지 설치, 제거, 갱신, 의존성, Define Symbol 적용을 Unity Editor 안에서 관리하는 도구입니다.
